# WEEKENDER MVP V2

地图驱动的城市旅行探索 MVP，Next.js 15 + React 19 + TypeScript + Leaflet + Zod。
当前目录最初为空，因此创建新项目，没有删除或重建任何已有代码。

## 项目链接

- **在线访问：[weekender-three.vercel.app](https://weekender-three.vercel.app/)**

## 启动

```sh
npm install
npm run dev -- --port 3010
```

打开 http://localhost:3010 。生产构建：`npm run build`；生产启动：`npm start -- --port 3010`。

可选：将 `.env.example` 复制为 `.env.local`，填写启用了 Routes API 的 `GOOGLE_MAPS_API_KEY`，重启服务。该密钥仅在服务端读取。未配置时公共交通路径与时间显示待验证。

## 已实现的端到端流程

1. 三步引导：地点定位/地址搜索，旅行天数和日期，总预算、币种、人数、交通、兴趣、节奏。
2. 大地图：起点和真实目的地种子标记、缩放平移、候选列表双向选择、修改条件、兴趣排序。可用道路/公共交通估时参与天数筛选；数据缺失只作为初步探索。
3. 逐日规划：真实 POI 规则草案、Day 切换、时间线、添加/删除/换序、首站时间和停留时长修改、交通切换、恢复当天草案。
4. 路线重算：编辑后取消旧请求，重算相邻站点；公共交通顺序查询对应出发时间的班次。任何未知路段使后续到达时间保持未知。仅绘制 OSRM 返回的真实道路几何。
5. 首日出发、末日返程分别查询；出发晚于首站目标时提示冲突。住宿区域为建议，没有虚构预订。
6. 本地自动保存、手动保存、刷新恢复、JSON 导出；Zod 及候选库校验防止损坏存储/虚构 POI 进入计划。
7. 按目的地和当天日期查询天气；预报范围外、网络错误均明确显示；雨天提供文化类替代候选，雷暴提示停止户外活动。

## 页面与模块

- `app/page.tsx`：应用入口；首页/探索/规划在同一客户端工作区切换。
- `components/Weekender.tsx`：引导、候选列表、规划时间线、费用面板、存储恢复。
- `components/Map.tsx`：独立 Leaflet 地图适配层，传入地点标记与已验证道路路径。
- `lib/model.ts`：Zod 契约、目录校验、规则草案、预算假设、时间传播。
- `lib/data.ts`：4 个悉尼周边目的地、24 个真实地点种子，含坐标和来源链接。
- `lib/services.ts`：客户端服务接口、时区与夏令时处理。
- `app/api/services/route.ts`：服务端地址搜索、路线、天气适配；密钥不下发浏览器。

## 数据与服务边界

| 功能 | 来源 | 说明 |
| --- | --- | --- |
| 底图 | OpenStreetMap 标准瓦片 | 需要网络；瓦片故障保留列表与标记 |
| 地址搜索 | Nominatim | 提交查询才请求，不做逐字请求；使用公共服务，生产环境需替换商业/自托管服务并加限流 |
| 目的地、POI | 人工整理的悉尼周边种子库 | 可核对地图与目的地官网；不是实时 Places 搜索 |
| 自驾路线 | OSRM 公共演示服务器 | 真实道路几何与模型估时，无实时路况；不是公共交通时间 |
| 公共交通 | Google Routes（可选密钥） | 使用旅行日期和 NSW 时区；公交/火车传对应模式约束；线路详情通过 Google Maps 打开，不把 Google 几何绘制到第三方地图 |
| 天气 | Open-Meteo | 16 天请求范围，以实际返回日期为准；不以出发地天气代替目的地天气 |
| 住宿与餐饮费用 | 明示的演示假设 | 住宿 AUD70–130/人/晚，餐饮 AUD25–45/人/天；非商家价格，非实时汇率 |
| 交通、活动费用 | 未接入可靠价格源 | 待确认，不以 0 元冒充免费，不确认预算可行性 |
| 拥挤程度 | 未接入 | 显示暂无可靠人流数据 |
| AI | 当前为明确标记的规则回退 | 未接大模型；草案只使用真实候选，不声称实时 AI 验证 |

任意城市可以定位或搜索。当前可规划候选库只覆盖悉尼周边；其他地区显示无候选数据，不将悉尼候选误称为当地推荐。规则草案不验证开放时间、门票预约和住宿供应，**不应声称已经生成可直接执行的完整行程**。要达到生产级可执行目标，还需真实 Places/开放时间/票价/住宿数据与路线复核，并将未知项补齐。

公共交通未配置密钥时，“悉尼、2 天 1 晚、A$300、自然、公共交通”的地图发现、编辑、保存流程可完整演示，但交通和最终预算仍待确认。1–7 天受支持，种子候选不足时留出空白日供用户补充，不重复编造地点。

未实现聊天和订票；个人行程分享为 JSON 文件。组队与成员共享行程已在 V3 实现，见下文。

### 真实后端与部署范围

此版本使用 **Node.js 24 内置 SQLite**，不使用 localStorage 模拟多人状态。账号、密码散列、会话、队伍、成员、申请、共享行程、举报全部在服务端数据库。默认文件 `data/weekender.sqlite`，已加入 gitignore；可通过 `WEEKENDER_DB_PATH` 指定持久卷路径。不要提交数据库或把数据库放入公开静态目录。备份时使用 SQLite backup 工具或停服后一并备份数据库相关文件。

适用于本地演示和具有持久磁盘的单实例 Node 部署，**不能直接部署到临时文件系统或多个互不共享数据库的 serverless 实例**。默认没有示例招募数据：请注册两个账号测试真实多人流程。浏览器测试使用单独的临时数据库，不污染正常预览数据。

Supabase Auth + PostgreSQL + RLS 已评估：它更适合托管认证、多实例和云部署，但当前没有 Supabase 项目凭据，因此没有假装连接云端。未来迁移时应以 `auth.uid()` 替换本地会话身份：公开 teams 仅含城市与招募信息；team_members 由队长审批事务写入；join_requests 申请人仅可创建自己的申请；trip_plans 仅成员可读、队长可写；reports 仅本人提交、管理员审核。接受申请必须通过带行锁的数据库函数完成容量检查和成员插入，不能仅依靠客户端或简单 RLS 条件。当前对应权限由同一服务端数据库事务实现。

### 表与权限

- `users` / `sessions`：独立账号名，公开昵称；scrypt 加盐密码散列；随机会话 token 只在数据库保存 SHA-256 散列。HttpOnly、SameSite Cookie，HTTPS 下 Secure；账号级登录尝试限制。
- `teams`：城市、日期、天数、全队预算区间及币种、兴趣、人数上限、介绍、队长、招募状态。
- `team_members`：队伍与用户联合主键，队长创建时自动加入。
- `join_requests`：队伍与申请人唯一约束；pending/accepted/rejected/withdrawn。拒绝后不可重复申请，成员主动退出后可重新申请。
- `trip_plans`：每队一份共享行程；只允许队长更新；继承现有 Zod + POI 白名单校验。
- `reports`：用户举报队伍的原因与时间。当前是持久化人工处理队列，没有自动审核或后台管理界面。

所有写操作重新核验服务器会话身份。审批使用 `BEGIN IMMEDIATE` 串行事务，同时检查队长、申请归属/状态、招募状态和容量；不信任浏览器传来的角色或成员 ID。同源请求检查阻止跨站写操作。SQL 使用参数绑定。

关联行程会将精确出发地址和坐标替换为所选城市中心，并从真实 POI 目录重建名称、来源和备注。公开队伍仅展示目的地摘要，未入队访客看不到完整路线及成员名单。创建页明确要求不得包含联系方式、精确住址和未经同意的集合地点，发布前确认；自由文本仍需要实际人工内容治理，未声称已自动识别所有敏感内容。

成员打开共享地图为只读；后端同样禁止成员修改。队长点击“保存行程”后持久化，其他成员刷新地图看到最新版本；队伍详情每 15 秒更新人数与申请，不声称 WebSocket 实时协作。共享编辑不会覆盖个人本地行程。
